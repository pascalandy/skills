# GPT Image 2.5 Flare and Sunburst: developer settings

**Research date: September 28, 2026.** OpenAI documents both models, but three details remain uncertain enough to affect request planning: the official pricing table conflicts with prose about GPT Image 2 rates; official mask limits differ between the guide and SDK; and support for setting `input_fidelity` on 2.5 is not confirmed. The choices below use the explicit pricing table and leave uncertain controls unset. <https://developers.openai.com/api/docs/pricing> <https://developers.openai.com/api/docs/guides/image-generation> <https://github.com/openai/openai-python/blob/main/src/openai/types/image_edit_params.py> [OFFICIAL]

## 1. IDs, release, endpoints, and ChatGPT

OpenAI announced GPT Image 2.5 on **September 8, 2026**. The API IDs are `gpt-image-2.5-flare` and `gpt-image-2.5-sunburst`; their documented pinned snapshots are `gpt-image-2.5-flare-2026-09-08` and `gpt-image-2.5-sunburst-2026-09-08`. <https://openai.com/index/introducing-chatgpt-images-2-5/> <https://developers.openai.com/api/docs/models/gpt-image-2.5-flare> <https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst> [OFFICIAL]

Both work through `POST /v1/images/generations` and `POST /v1/images/edits`. In `POST /v1/responses`, set a supported mainline model at the top level and select Flare or Sunburst inside its `image_generation` tool. Batch accepts `/v1/responses`, `/v1/images/generations`, and `/v1/images/edits`. <https://developers.openai.com/api/docs/guides/image-generation> <https://developers.openai.com/api/docs/guides/batch> [OFFICIAL]

ChatGPT Images 2.5 was announced for ChatGPT, ChatGPT Work, and Codex across tiers and surfaces. **Which of Flare or Sunburst serves any particular ChatGPT surface: NOT FOUND.** OpenAI presents the two names as API choices, without publishing ChatGPT’s routing. <https://openai.com/index/introducing-chatgpt-images-2-5/> [OFFICIAL]

## 2. Model choice, latency, price, and access

Flare is the small, speed-oriented model for routine creation and editing; Sunburst is the base, quality-oriented model for demanding visual work and precise edits, with longer generation times. The prompting guide calls Flare’s image quality *comparable* to GPT Image 2, while the launch announcement calls it *higher-quality* than GPT Image 2; neither supplies a common numeric quality measure, so treat these as qualitative descriptions rather than a guaranteed ranking for a workload. <https://developers.openai.com/api/docs/guides/image-prompting> <https://openai.com/index/introducing-chatgpt-images-2-5/> [OFFICIAL]

OpenAI reports up to **50% lower latency** for Flare than GPT Image 2, but publishes **no typical seconds-per-image table by model, quality, and size**. Its guide says complex prompts can take up to two minutes and advises measuring the actual workflow. <https://openai.com/index/introducing-chatgpt-images-2-5/> <https://developers.openai.com/api/docs/guides/image-generation> [OFFICIAL]

For a concrete but **THIRD-PARTY** observation, one 1024×1024 PNG benchmark reported median completion times, from at most three attempts per cell, of **10.4/13.8/18.1/26.7/45.6 seconds** for Flare and **15.7/18.1/29.9/46.7/85.0 seconds** for Sunburst at `low/medium/high/xhigh/max`. These are small-sample workload results, not OpenAI latency targets. That article also applies the same token rates to GPT Image 2 as to 2.5, contrary to OpenAI’s current price table; use its timing observations only. <https://genflick.com/blog/gpt-image-2-5-cost-speed-benchmark> [THIRD-PARTY]

**Standard token rates are identical for Flare and Sunburst**, per million tokens:

| Token type | Input | Cached input | Output | Source URL |
|---|---:|---:|---:|---|
| Text | $5.00 | $1.25 | No text output charge | <https://developers.openai.com/api/docs/pricing> [OFFICIAL] |
| Image | $8.00 | $2.00 | $30.00 | <https://developers.openai.com/api/docs/pricing> [OFFICIAL] |

There is **no fixed per-image API price**: total cost depends on text input, reference-image input, image-output tokens, optional partial images, and, in Responses, the mainline model’s usage. Flare and Sunburst can consume different output-token counts at the same named quality and size. Cached image-generation input rates apply to the **Responses image tool only**, not direct Images API calls; cached hits affect billing but their token counts are not exposed in Responses `usage`. <https://developers.openai.com/api/docs/guides/image-generation> [OFFICIAL]

A **THIRD-PARTY** transcription of an OpenAI calculator snapshot gives 1024×1024 *output-only* estimates of `low` 196 tokens/$0.00588, `medium` 439/$0.01317, `high` 1,756/$0.05268, `xhigh` 3,122/$0.09366, and `max` 7,024/$0.21072. The accessible official page exposes only its calculator’s initial **196 tokens/$0.00588** state, so the full sequence and its model selection could not be independently verified; do not treat it as a guaranteed table for both models. <https://www.linkmodel.ai/blog/gpt-image-2-5-api-pricing> [THIRD-PARTY] <https://developers.openai.com/api/docs/guides/image-generation> [OFFICIAL]

**Pricing conflict:** both 2.5 model pages and the API changelog say their token rates “match GPT Image 2,” but the live numeric pricing table lists GPT Image 2 at **half** the 2.5 rates: $2.50 text input, $0.625 cached text, $4 image input, $1 cached image, and $15 image output per million. Use the explicit numeric pricing table and confirm billing for a production estimate; it agrees with the numeric 2.5 model-page prices and the image-generation guide. <https://developers.openai.com/api/docs/pricing> <https://developers.openai.com/api/docs/models/gpt-image-2.5-flare> <https://developers.openai.com/api/docs/changelog> <https://developers.openai.com/api/docs/guides/image-generation> [OFFICIAL]

Both model pages list **Free: unsupported**; Tier 1 **100,000 TPM/5 IPM**; Tier 2 **250,000/20**; Tier 3 **800,000/50**; Tier 4 **3,000,000/150**; Tier 5 **8,000,000/250**. Organization verification **may** be required; OpenAI does not state that it is required for every organization. <https://developers.openai.com/api/docs/models/gpt-image-2.5-flare> <https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst> <https://developers.openai.com/api/docs/guides/image-generation> [OFFICIAL]

Batch offers a **50% discount**, separate higher rate limits, and a 24-hour completion window. A Batch JSONL input file can contain requests for only one model; OpenAI lists image edits as supported but gives no concrete Batch edit-image encoding example. <https://developers.openai.com/api/docs/guides/batch> [OFFICIAL]

## 5. Official 2.5 prompting guidance

Start with the deliverable and its intended use, then describe **subject, composition, style, and constraints**. Complex briefs can use labeled sections such as scene, subject, details, and constraints; OpenAI does not claim special syntax is required. Keep API controls such as `size`, `quality`, and `background` in request fields rather than trying to set them only in prose. <https://developers.openai.com/api/docs/guides/image-prompting> [OFFICIAL]

For photographs, specify framing, subject scale and interaction, lighting, texture, and the visual effect of camera language. The guide’s sailor example pairs an eye-level medium close-up and 35mm-film look with soft coastal light, visible skin texture, and an instruction against heavy retouching; camera terms guide appearance rather than guarantee physical camera simulation. <https://developers.openai.com/api/docs/guides/image-prompting> [OFFICIAL]

For **exact text**, quote the required copy, say where and how it should appear, specify its occurrence count, and exclude unwanted text, logos, and watermarks. One official ad example asks for the tagline **“Yours to Create.”** exactly once; inspect spelling and legibility afterward, especially with small type or dense information. <https://developers.openai.com/api/docs/guides/image-prompting> [OFFICIAL]

For diagrams, charts, slides, scientific visuals, and interfaces, give the audience and purpose, canvas and hierarchy, verified labels/data, placement, and legibility requirements. The guide favors concrete panels or visual beats for comics, usable interface structure for UI previews, and a review of factual relationships rather than appearance alone for explanatory graphics. <https://developers.openai.com/api/docs/guides/image-prompting> [OFFICIAL]

For edits, state **what changes and what remains invariant**: identity, pose, geometry, composition, camera, light, surroundings, labels, and style as applicable. When using several reference images, identify each by index and role, such as subject from image 2 and setting from image 1; for translation, ask to change the text while retaining the layout and inspect for untranslated remnants. <https://developers.openai.com/api/docs/guides/image-prompting> [OFFICIAL]

For sketch-to-render and style transfer, identify which source attributes to carry over and forbid invented objects or copy when they would violate the brief. For transparent work, combine the prompt for an isolated subject with `background:"transparent"` and inspect the decoded alpha channel. For a sequence, reuse the chosen result or character reference, request one narrow change per turn, repeat critical invariants, and inspect drift after every edit. <https://developers.openai.com/api/docs/guides/image-prompting> [OFFICIAL]

The guide’s migration procedure is to save representative prompts and references, compare a candidate with settings held constant, evaluate the complete editing sequence, then tune **one** quality setting at a time and measure typical and slow latency, retries, and cost per accepted result. Its runnable “complete example” still uses `gpt-image-2` as a baseline, so substitute a 2.5 ID and supported settings when using it for this task. <https://developers.openai.com/api/docs/guides/image-prompting> [OFFICIAL]

## 6. Limitations and operational gotchas

Text placement and clarity, recurring character or brand consistency, and precise structured composition can still fail. Inspect hands and other anatomy as part of visual review, but an OpenAI 2.5-specific hand-error rate is **NOT FOUND**. Complex prompts may take up to two minutes; no official quality-by-size timeout or latency table is published. <https://developers.openai.com/api/docs/guides/image-generation> [OFFICIAL]

A mask is **prompt guidance**, not an exact clipping boundary. Repeated edits can change supposedly preserved details; if a region must remain pixel-identical, composite the approved edit into the original using an image editor. <https://developers.openai.com/api/docs/guides/image-generation> <https://developers.openai.com/api/docs/guides/image-prompting> [OFFICIAL]

Transparent output requires PNG or WebP and inspection of actual alpha, particularly near hair, glass, shadows, and object edges. JPEG is unsuitable for transparent output. Sizes above `2560x1440` pixels in total area are experimental; verify the dimensions of the returned asset rather than inferring them from a “4K” phrase in the prompt. <https://developers.openai.com/api/docs/guides/image-prompting> <https://developers.openai.com/api/docs/guides/tools-image-generation> [OFFICIAL]

Prompts and outputs are filtered. `moderation:"low"` is less restrictive, but it does not switch checks off; `moderation_blocked` errors can distinguish input versus output stages, while `image_generation_user_error` should prompt a changed request rather than an automatic identical retry. <https://developers.openai.com/api/docs/guides/image-generation> [OFFICIAL]

OpenAI says Images 2.5 continues to use **C2PA metadata and invisible watermarking**.
