## Local conversation and documentation rules

Conduct the interview in conversation by default. Reading project documents does not authorize writing documentation or implementing the resulting plan.

When the user requests glossary or ADR documentation, or a calling workflow includes it in the authorized scope, resolve the `matt-mode` package. Read its `references/local-adaptations.md` and `playbooks/domain-modeling/domain-modeling.md`, then follow the domain procedure and its formats. Preserve the caller's task. If the user requests a different document, produce that document instead of inventing a glossary or ADR.

Capture authorized documentation during the interview. Wait for unresolved human choices, and keep implementation separate from agreement on the plan. Honor prior approvals without asking for them again. If the user resumes conversation-only work, stop documentation writes.

Use available background agents for bounded research and inspection, preserving the caller's scope. If delegation is unavailable, investigate facts directly and report that limitation. Planning work never delegates implementation.
