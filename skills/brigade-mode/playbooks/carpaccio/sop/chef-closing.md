# chef-closing

Apply [Statuses, Messages and Decisions](../carpaccio.md#statuses) at phase entry and turn end. Keep the received Cook phases, frozen heads and stack diff for each approval.

## Validate and merge

1. On `🍽️ Stack ready`, read the Report of the Cook and its `report.md`, including rejected findings. If you disagree with a rejected finding, give your reason and return the Cook's worktree through Fix. Check conflicts between Cooks. Wait for every counted Cook to serve and for checks on all frozen heads to finish before sending `🍽️ Batch ready`. Done when the reports and checks support your merge confidence
2. Apply the merge rule in [Decisions](../carpaccio.md#decisions). If the rule lets you merge, record the authorization, show 🔀 and send `🔀 Batch merging` with the Report to the Head Chef. Then go to step 3. Otherwise, send `🍽️ Batch ready` with the Report, show 🍽️ and wait until the Head Chef relays Pascal's decision. `⏳ Rework` returns affected Cooks to Fix; `🍽️ Hold` keeps the batch ready; `⏹️ Drop` cuts the batch, sends `⏹️ Stop` to its Cooks and goes to Closing. Done when the notice is sent, `🔀 Merge` is received for current heads, or the cut is recorded
3. Show 🔀 while merging. Merge one stack at a time from the frozen Cook worktree, after checking its checkout is clean and pushed and GitHub holds the approved heads. Compare the stack's own diff after a restack: if only its base changed and checks pass, keep the approval and the Cook's 🍽️. If its own diff changed, get a new merge decision. Check GitHub before retrying an uncertain merge. Use the project's merge procedure: for a single PR its merge command; for a stack 🧰 gh-stack Land, then the project's deploy. In skills, use `just merge` on the merged top branch for that deploy. Run the merge command bare, with no pipe or redirect, so its permission rule matches. Read the whole output, since an exit 0 may hide a failed deploy. Before the next stack, ask its Cook to restack on `main` and return fresh `🍽️ Stack ready`. Done when GitHub confirms the approved stack merged and the deploy result is recorded
4. On failure, record landed PRs, send the Cook the cause and return its worktree for Fix. Tell the Head Chef if a previously ready batch lost readiness, so it withdraws its merge item. Report the partial outcome. Resume at step 1 after fresh `🍽️ Stack ready`. Done when each stack merged in order or the Head Chef has an unresolved blocker
5. After the last stack, tell each Cook `merged` and send the Head Chef `Batch merged` with deploy results. For `Release: yes`, follow the remaining repository release procedure from `main`; check its outcome before retrying an uncertain release and report a failure before closing. Done when all merge and release outcomes are recorded

If Pascal says Stop, finish a merge already running, discard unused approval and follow `chef-run` Stop. A frozen watch wake that brings a finding, such as a failed check, a review or comment, or a conflict, invalidates readiness until you return the worktree, the Cook triages it and sends fresh `🍽️ Stack ready`. Tell the Head Chef to withdraw a pending merge item. A wake reporting only passing checks preserves readiness.

## Closing

For a batch without PRs, begin here.

1. Show 🧹. For an Epic, read every child's state. Open children outside the batch are reported and may remain open. An open child inside the batch blocks ⛳ until completed or cut by Pascal. Close the Epic with proof when all its children are closed. Done when no Epic applies, or all in-batch children are done or cut and the remaining open children are reported
2. Ask every Cook to close, whether retros are enabled or not. Each Cook runs enabled retros, unwatches, reports and settles. Do the Chef's retros if `[chef].retro`. Done when every Cook has a final phase and each enabled retro has issue links or a no-findings result
3. Confirm each Cook is settled with 🧰 t3-runtime. Remove worktrees that are clean and merged, retaining the rest with a reason. Done when every Cook is settled and every worktree is removed or accounted for
4. Compute ⛳ only when all in-scope stacks merged or a no-PR batch did its own work, the release is done or cut, all in-batch Epic children are done or cut, and every Cook is final and settled. Otherwise after Stop or a whole-batch cut, compute ⏹️. Send `⛳ Batch delivered` or `⏹️ Batch stopped` with the Report and set the title to the final status. As the last step before settling, delete your Watchdog's schedule, cancel its task and remove its work folder. Keep your own work folder; the Head Chef removes it at Close. Then settle. Done when the Head Chef received the outcome, no Watchdog schedule remains and your settle returns `settlesWhenTurnEnds: true`
