# Explanatory media

## Presentation, narrative essay, and case study

Use a guiding question, evidence, selective chronology, decisions, consequences, and a
change in understanding.

**Central diagnostic**

Does the story illuminate the claim without replacing its proof?

## Technical README and project page

Use immediate relevance, a concrete problem situation, a concise project response,
one representative workflow, examples as proof, explicit boundaries, and progressive
disclosure.

The first screen should let the intended reader decide whether the project matters
before requiring technical detail.

**Central diagnostic**

Can the reader identify the project's fit before reaching installation or API detail?

## Project video and live demo

Use a spoken point of view, recognizable friction, early payoff, visual proof, one
guided task, rationale, and honest tradeoffs. Use first-person origin only when the
sources support it.

**Central diagnostic**

Do the story and demonstration form one causal sequence?

## Technical walkthrough and architecture explanation

Use a user or system goal as the spine. Introduce components when they become causally
necessary. Show concrete data or control flow and keep depth proportional to the
audience's decision.

Use diagrams only when they reduce conceptual load.

**Central diagnostic**

Does each technical detail answer a question the audience now has a reason to ask?
