# Diagram

1. Name the question the diagram answers. Read [diagram techniques](../references/diagram-techniques.md) to choose notation and rendering method. Decide what must remain visible together and what can appear on demand. Finish when one visual grammar explains the primary relationship.
2. Build the smallest model that preserves that meaning. Add sequencing, filtering, path tracing, or pan and zoom only when it answers a real follow-up question. Keep the surrounding composition subordinate to labels, relationships, and notation. Finish when the default view communicates the system without interaction.
3. Run shared verification and the technique reference's applicable checks. Inspect label collisions, clipped nodes, connector routing, sequence endpoints, keyboard access, and every interactive state. Finish when the relationships remain legible at both widths and every intentional simplification is accounted for.

Return the diagram form, main simplifications, and assumptions.
