# Wireframe

1. Identify user, task, bounded screen or flow, required information and actions, and structural questions. Use real labels and representative content. Finish when the reviewer can name the product decision under test.
2. If the user chose a structure, use it. Otherwise, create two or three distinct directions when structure is unsettled. Vary navigation, grouping, action placement, density, or mobile reflow. Keep the same task and core content. Give directions descriptive names and one sentence per tradeoff. Finish when alternatives show different structural decisions.
3. Use system type, restrained grayscale, plain borders, and labeled media placeholders. Follow the active theme policy. Defer visual polish. Add click-through behavior only to test navigation or disclosure. Where practical, keep directions in one file, with an accessible comparison selector if needed. Finish when each direction has enough content to judge its layout.
4. Run shared verification. Test every modeled click path. Confirm directions remain structurally distinct at desktop and mobile widths. Finish when structure, reading order, and scope boundaries are clear at both widths.

Return directions, tradeoffs, open structural questions, and visual decisions deferred to a mockup or prototype.
