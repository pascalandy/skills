# Wireframe

1. Identify the user, task, bounded screen or flow, required information and actions, and structural questions. Use real labels and representative content. Finish when the reviewer can tell which product decision the wireframe tests.
2. When structure is unsettled, create two or three distinct directions that vary navigation, grouping, action placement, density, or mobile reflow. Preserve the same task and core content across directions. Use descriptive names and a sentence about each tradeoff. If the user already chose a structure, use that direction. Finish when the alternatives expose different structural decisions rather than cosmetic changes.
3. Build with system type, restrained grayscale, plain borders, and labeled media placeholders. Follow the active theme policy. Keep visual polish deferred so the review stays on hierarchy and flow. Add plain click-through behavior only when it helps test navigation or disclosure. Keep directions in one file when practical, with an accessible comparison selector if needed. Finish when each direction is inspectable with enough content to judge its layout.
4. Run the shared verification. Check every modeled click path and confirm that the directions remain structurally distinct at desktop and mobile widths. Finish when the structure, reading order, and scope boundaries are clear at both sizes.

Return the directions and tradeoffs, open structural questions, and visual decisions deferred to a later mockup or prototype.
